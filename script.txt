TLPFA: A Web-Based Transaction Lifecycle Traceability Platform for Financial Administrative Operations at Visayas State University Alangalang

It means the platform will be accessed through a web browser rather than being a standalone desktop application.Our title means that we are proposing a web-based platform that will allow authorized personnel to record, track, and monitor financial administrative transactions throughout their lifecycle, from initiation to completion.

PROJECT CONTEXT

Our project context explains that financial transactions go through different stages, so it is important to have organized information about their progress and history. The supporting studies show the importance of financial records, traceability, and audit trails. Based on these, we propose a centralized platform for tracking transaction activities from initiation to completion.

PURPOSE AND DESCRIPTION

The main purpose is to develop a platform that supports the traceability of financial and administrative transactions.Our respondents are selected financial and administrative personnel because they are involved in handling these transactions. Their experience can help us understand the current procedures and requirements that should be considered in developing the platform.

 4. PROBLEM STATEMENT / ROOT CAUSE

 Problem 1: Time-consuming preparation and processing

Some financial processes can take time when activities are handled manually.

 Problem 2: Irregularities in financial transactions

Your proposal says unusual or anomalous transactions can be difficult to identify without systematic analysis.

Tien et al. (2024) discusses financial anomaly detection.

Your proposed system **does NOT automatically detect fraud or anomalies.

Does your system detect fraud?

No. Our proposed system does not automatically detect fraud. Its main purpose is to record, track, and document transaction activities so authorized personnel can review the transaction history and progress.

Problem 3: Limited tracking of transaction progress

This is probably the most directly connected problem to your title.

Your proposal explains that transaction events may be recorded across different activities, making the complete transaction flow less visible from initiation to completion. Jans & Eulerich (2022) supports this area. 

 GENERAL OBJECTIVE

To develop a centralized platform that tracks financial transactions from initiation to completion and provides organized transaction information for financial administrative operations. Create one platform where transactions can be tracked from beginning to end.

 SPECIFIC OBJECTIVES

 Objective 1

Create a centralized place for recording and tracking transactions throughout their lifecycle.

 Objective 2

Add an activity log that records:

* user actions,
* transaction updates,
* process changes.

 Objective 3

Provide an organized transaction history so authorized personnel can see the status and progression of transactions.

 Easy way to remember:

Record → Log → History

SCOPE AND LIMITATIONS

Your project is limited to financial administrative operations at VSU Alangalang.

It will help authorized personnel:

* record transactions,
* track transactions,
* monitor transactions,
* view transaction history.

It will only cover the selected offices, users, and financial processes included in the study. 

Does your system replace the existing accounting system?

No. Our proposed platform will not replace existing accounting or financial management systems. It will focus on transaction tracking and documentation.

 FUNCTIONS

1. Role-Based Access

Different users have different permissions based on their responsibilities.

 2. Transaction Registration

Authorized personnel enter transaction information and receive a unique reference number.

 3. Transaction Status Tracking

Users can see the current stage of a transaction.

4. Activity Logging

The platform records user actions, updates, and changes, including date and time.

5. Transaction History

Shows the chronological activities and status changes.

 6. Search and Filtering

Users can find transactions using reference number, date, or status.

 7. Monitoring Dashboard

Provides an overview of transactions such as:

Pending | Ongoing | Completed

 Easy memory:

Access → Register → Track → Log → History → Search → Dashboard

 DEVELOPMENT PLAN

You are using the Iterative Model.

That means you don't try to build everything at once.

You build the system in cycles.

For example:

 First cycle:

Login + accounts + transaction registration

 Later cycles:

Status tracking + activity logging + history + search + dashboard

Each cycle is tested and improved. 

Your architecture is Laravel MVC.

MVC separates:

Model → data
View → interface/presentation
Controller → application logic

Your proposal also specifies Laravel/PHP, MySQL, Bootstrap, HTML/CSS/JavaScript, SweetAlert2, and Chart.js.
